[Heading2] Ngữ cảnh
[ListParagraph] Cả hai app đều xoay quanh FastBusiness ERP và định dạng file điều khiển "FCode" (controller XML kiểu Dir/Grid/Filter/Report, kèm SQL và JavaScript nhúng bên trong) — nhưng phục vụ hai vai trò khác nhau, chạy như hai tiến trình WinForms .NET 8 độc lập, không tham chiếu project lẫn nhau, mỗi app có file settings JSON riêng trong %AppData%\Bcode.
[ListParagraph] Bcode.App là bản dựng lại đầy đủ bộ công cụ FCode gốc của FastBusiness: quản trị SQL (query, table edit, schema compare, backup DB, SQL Profiler), cây lệnh WCommand (menu ERP), sinh gói update/insert (Gen Update, Advance Note + Gen All), cấp source chuẩn từ kho (Add Source) và nhân bản danh mục (Clone danh mục), thư viện snippet, đối chiếu file, giải mã đối tượng SQL, xuất báo cáo/XLSX, khai báo & sinh đặc tả API, tự động đăng nhập/tra cứu dự án FSG… Từ bản cập nhật gần nhất app mở bằng màn hình Projects (chọn project, có thể mở nhiều cửa sổ Bcode song song, mỗi cửa sổ một dự án), có AI (Claude/Gemini) gợi ý code ngay trong SQL Query, và phần lớn hộp thoại mới được vẽ bằng một trang WebView2 — hướng tới người quản trị/triển khai hệ thống ERP tại khách hàng.
[ListParagraph] BcodeViewer.App ra đời sau, là một trình xem/soạn file nhẹ hơn, xây trên Monaco Editor (lõi của VS Code) thay vì các control WinForms tự viết — tập trung vào trải nghiệm gõ code hiện đại: IntelliSense nhiều lớp cho đúng cú pháp FCode (kèm bộ snippet gốc của FCodeViewer), F12/Peek xuyên file cho entity include, Ctrl+G nhảy nhanh tới tag, xem trước màn hình Dir (Alt+P), dịch caption v→e, clone file, chạy SQL nhanh, F5 mở menu của file trên trình duyệt, và một lớp AI (Claude hoặc Gemini) hỗ trợ gợi ý code theo kiểu Copilot. BcodeViewer dùng lại đúng danh sách workspace/kết nối CSDL mà Bcode.App đã lưu (SqlSchemaService đọc chung %AppData%\Bcode\settings.json), nên người dùng không phải khai kết nối riêng lần nữa — nhưng không có các công cụ quản trị ERP nặng ký (backup DB, WCommand, gen update, SQL Profiler…) mà Bcode.App có.
[ListParagraph] Hai app nói chuyện với nhau: Bcode.App mở BcodeViewer.exe từ File Lookup (nút Edit / nhấp đúp, kèm tên project để BcodeViewer nhóm file đúng dự án); 
[ListParagraph] BcodeViewer chạy một bản duy nhất cho mỗi phiên Windows (Mutex + named pipe BcodeViewer.SingleInstance.<session>), nên file mở thêm sẽ rơi vào cửa sổ đang chạy.
[ListParagraph] Ngược lại Bcode.App vẫn lắng nghe pipe Bcode.Control.<session> (Services/ViewerControlServer.cs) nhưng hiện BcodeViewer không còn gửi lệnh vào đó — F5 trong BcodeViewer tự mở menu bằng trình duyệt mặc định (Host/MenuLauncher.cs). Cả hai dùng chung một bản sao y hệt của BcodePaths.cs để cùng chọn đúng thư mục %AppData%\Bcode kể cả khi %AppData% không ghi được trên máy đó.

[Heading2] Sơ đồ kiến trúc
[ListParagraph] Cả hai app đều là WinForms + WebView2 lai: khung native (WinForms) lồng các vùng render bằng HTML/JS cục bộ qua WebView2, nhưng cơ chế host↔JS khác hẳn nhau. Ở Bcode.App ngày càng nhiều màn hình là một trang WebView2 nguyên khối (searchbox, advnote, addsource, editproject, changeowner, filereference, aihistory, wcommandedit, quickaccess, findbar…) — C# chỉ giữ phần đụng tới dữ liệu và nhận/gửi message {action, data}.
[-] 
[ListParagraph] Điểm khác biệt chính: Bcode.App dùng postMessage qua WebMessageReceived (bất đồng bộ, JSON thô, mỗi control WebView2 — topbar, iconrail, statusbar, sqleditor… — tự nhận và xử lý message riêng, không có điểm bridge chung), còn BcodeViewer dùng host object COM (EditorBridge, [ComVisible(true)]) với quy ước Begin<Ten>(requestId,...) + web message hostCallResult để trả kết quả không chặn luồng UI — vì BcodeViewer cần gọi mạng (Anthropic/Gemini API) trên đường gõ phím, thời gian thực, nên kiểu đồng bộ cũ sẽ treo cửa sổ.
[ListParagraph] EditorBridge có 2 kiểu phương thức: các Notify* (ví dụ NotifyCursorChanged, NotifyFileOpened, NotifyFileClosed, NotifyDirtyChanged) chạy đồng bộ ngay trên luồng UI vì chỉ cập nhật state trong bộ nhớ (không đụng file/mạng/CSDL); còn mọi thứ đụng tới filesystem, SQL Server hay API AI bắt buộc đi qua Begin* — xếp hàng qua Host/AsyncHostCall.cs trên luồng thread-pool, có nhóm CompletionGroup để tự hủy request ghost text cũ khi có request mới (gõ nhanh không dồn cục các cuộc gọi). Ngoài ra có vài hàm Get* trả JSON đồng bộ MỘT lần cho trang (GetSnippets, GetFcodeHints, GetTheme, GetEditorConfig, GetSettings…) để gõ phím không phải gọi host liên tục. Hiện EditorBridge có hơn 50 phương thức public — xem chi tiết ở mục "Cầu nối host ↔ JS" cuối phần BcodeViewer.App.

[Heading1] Bcode.App — tính năng & file
[ListParagraph] Program.cs chỉ gọi Application.Run(new MainForm()) — toàn bộ việc dựng service nằm ngay trong constructor của Forms/MainForm.cs (không dùng DI container, mỗi service được new trực tiếp). Dữ liệu cục bộ (settings.json, snippet, ghi chú, AdvanceNotes, ai-history.json, FileLookupCache…) nằm dưới %AppData%\Bcode — BcodePaths.cs tự thử Roaming → Local → UserProfile → thư mục .exe và nhớ nơi đầu tiên ghi được. Khi mở app, màn hình Projects hiện ra để chọn project (Ctrl+Shift+N mở thêm cửa sổ mới chạy song song).

[Heading2] Cầu nối host ↔ JS
[ListParagraph] Host/EditorBridge.cs là hậu đài duy nhất: mọi thao tác đụng đến file/mạng/CSDL đi qua Begin<Ten>(requestId, ...) — hàng đợi không chặn UI — trả kết quả qua web message hostCallResult; Web/hostcall.js bọc lại thành Promise (window.bcodeHost.call(...)). Host/AsyncHostCall.cs là cơ chế hàng đợi/hủy đó.
[ListParagraph] Ngoài nhóm đã biết từ đầu (BeginInlineCompletion, BeginSaveAiSuggestionAsHint, BeginSearchWorkspace, NotifyCursorChanged, NotifyFileOpened), EditorBridge có thêm nhiều Begin*/Notify*/Get* — các nhóm chính:
[ListParagraph] BeginReadFile / BeginWriteFile — tự dò và giữ nguyên encoding gốc theo BOM (UTF-8/UTF-16 LE/BE/UTF-32), khắc phục lỗi ghi đè file .f UTF-16 thành UTF-8 khiến FastBusiness Online báo lỗi XML khi nạp lại.
[ListParagraph] BeginSaveWithHistory — lưu file kèm chụp snapshot nội dung cũ vào local history TRƯỚC khi ghi đè, có khóa theo từng đường dẫn.
[ListParagraph] BeginGetFileHistory / BeginGetHistorySnapshot / OpenHistoryFolder — liệt kê, đọc lại và mở thư mục chứa các phiên bản lịch sử.
[ListParagraph] BeginChooseSaveAsPath — mở hộp thoại "Save As" gốc Windows chạy nền (tránh modal đè lên lời gọi WebView2 đang chờ).
[ListParagraph] OpenFolder / BeginListDirectory — mở Explorer tại thư mục, liệt kê nội dung 1 cấp thư mục dạng JSON.
[ListParagraph] BeginPathsExist — kiểm tra tồn tại hàng loạt đường dẫn cùng lúc (dùng để validate <!ENTITY SYSTEM> trong problems.js).
[ListParagraph] BeginGetFileWriteTimeUtc — trả thời điểm ghi cuối của file, để trang phát hiện "file đã đổi ở máy khác".
[ListParagraph] BeginReplaceInWorkspace — Replace-all trên danh sách file đã chọn từ kết quả Find in Files.
[ListParagraph] NotifyFileClosed / NotifyDirtyChanged — báo trạng thái đóng file / thay đổi chưa lưu để MainForm cập nhật tiêu đề cửa sổ và xử lý đóng an toàn.
[ListParagraph] BeginCloneFiles / BeginGetHashSource / BeginRunMenu — nhân bản nhóm file cùng tên gốc; băm SHA-256 + ngày sửa của file và các file cùng tên gốc trong Controllers/Main của site; F5 lưu rồi mở menu của file bằng trình duyệt mặc định (MenuLauncher).
[ListParagraph] GetSettings / BeginSaveSettings / BeginChooseFolder / BeginChooseFile — trang Settings (Web/settings.js) đọc/ghi cấu hình; các hộp chọn thư mục/file vẫn là của Windows chạy nền.
[ListParagraph] BeginLoadHintSnippets / BeginSaveHintSnippet / BeginDeleteHintSnippet / BeginExportHintSnippets / BeginListFileTemplates / BeginReadFileTemplate / BeginCreateFromTemplate — Hint Code và File > New from Template vẽ trong trang (Web/templates.js).
[ListParagraph] BeginAskAI — hỏi AI kèm ngữ cảnh file đang mở (nội dung + đường dẫn), dùng cho Ctrl+I / chat.
[ListParagraph] GetSnippets / GetFcodeHints / GetTheme / GetEditorConfig / GetWorkspaceRoot / BeginGetSqlTables / BeginGetSqlColumns — dữ liệu đẩy cho trang một lần (snippet, gợi ý FCode, theme, cấu hình editor, gốc workspace, schema SQL) để gợi ý chạy hoàn toàn trong bộ nhớ trang.
[ListParagraph] Nguyên tắc Notify* (đồng bộ, chỉ cập nhật state trong bộ nhớ) vs Begin* (bất đồng bộ, đụng file/mạng/CSDL) vẫn không đổi.
